# 全局网络代理层与云端凭据管理架构决策

Handy-Cloud 需通过外部 HTTP API 调用云端语音转写（如 Google Gemini）与大模型后处理服务，必须在桌面端可靠处理网络代理，并在设置变更时免重启即时生效。

## 决策内容

1. **代理默认策略与配置存储**：
   - 默认模式为 `ProxyMode::System`（自动跟随操作系统代理）。Windows 端复用已有 `winreg` 依赖读取系统注册表代理，非 Windows 端探测标准环境变量；若未检测到系统代理则自动直连。
   - 提供 `None`（直连）与 `Custom`（自定义代理地址）选项。
   - 配置项以嵌套结构 `proxy: ProxySettings` 持久化在 `AppSettings` 中。

2. **全局客户端生命周期与热重载**：
   - 在 Tauri 托管状态中注册 `Arc<NetworkManager>` 单例，内部持有 `Arc<RwLock<reqwest::Client>>`。
   - 所有对外 HTTP 请求（云端 STT、LLM 后处理、版本更新检查）统一从 `NetworkManager::client()` 获取共享连接池客户端。
   - 当用户在前端修改代理配置时，后端在内存中原子替换内部客户端，新发起的请求即刻生效，无需重启应用。

3. **保存校验与快速失败**：
   - 用户输入自定义代理 URL 时，在保存时立即进行 URL 格式与协议合法性校验，非法地址直接返回错误并拒绝保存，防止损坏当前可用网络出口；同时提供独立的连通性探测命令供前端“测试连接”。

4. **凭据安全存储与前端交互**：
   - 在 `AppSettings` 中新增独立的 `cloud_stt_api_keys: SecretMap`，与现有的 `post_process_api_keys` 保持完全一致的存储模式，原生兼容便携模式（Portable）。
   - Rust 后端 `SecretMap` 的 `Debug` 实现自动脱敏为 `[REDACTED]`，杜绝日志泄露。
   - 前端采用带显示/隐藏眼睛图标的标准密码输入框交互。

## 备选方案与否决原因

- **否决默认纯直连（`ProxyMode::None`）**：目标用户在受限网络环境下通常已运行系统级代理工具，默认直连将导致首次发起云端请求直接超时失败，体验割裂。
- **否决无状态按需临时构建 Client**：高频转写请求频繁重新进行 DNS 查询和 TLS 握手，连接池复用率归零，显著增加端到端延迟。
- **否决 OS 原生凭据库（Keyring）**：引入额外的 Native C 库依赖，增加构建复杂度，且无法支持免安装的便携化使用场景。
